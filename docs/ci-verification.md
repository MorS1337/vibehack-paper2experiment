# Проверки CI и локальное повторение

Workflow [CI](../.github/workflows/ci.yml) запускается на push в `main`, на pull
request и вручную (`workflow_dispatch`). Два независимых job используют
`ubuntu-24.04` и `macos-15`, Node **22.19.0** и Python **3.12**. Действия GitHub
закреплены по SHA, зависимости приложения устанавливаются через `npm ci` из
`package-lock.json`. Ошибка одного job не отменяет другой.

В каждом job:

1. Проверяются Python `venv`/`ensurepip`, `ps` и `tar`.
2. `npm run build` выполняет `tsc --noEmit` и собирает production main/preload/renderer.
3. `npm test` запускает весь node:test suite, в том числе настоящие Python-процессы,
   потоки логов, отмену, дедлайны, TERM-resistant потомков, отсутствие отложенного
   вывода, архивы и проверки артефактов.
4. `npm run smoke` выполняет реальный Python/venv через `LocalBackend` и проверки,
   описанные ниже. Ненулевой exit status проходит через `tee` благодаря `pipefail`;
   retries и `continue-on-error` не используются.
5. Vast отключён release-policy: suite проверяет отсутствие billable requests,
   честный unavailable-статус и возможность recovery/cleanup прежних ресурсов.

## Научная воспроизводимость smoke

План и Python демо — явные заглушки агента, скопированные из открытого эталона.
Само исполнение, CSV, график, метрики и независимый пересчёт настоящие.

Smoke берёт параметры из плана, записывает `config.json` и `plan.json`, готовит
чистый venv и запускает проект. После независимой проверки удаляет каталог
артефактов и исполняет **сохранённую `run.command` из другой cwd**, используя путь
проекта с пробелами. Проверка повторяется для default-плана и изменённого плана
с другими `p`, `epsilon`, `n_values`, `trials_per_n`, `primary_n` и seed.

Для каждой пары запусков должны совпасть SHA-256 всего `samples.csv` (включая
каждый sample count) и независимо пересчитанные метрики. `config.json` и
сохранённый план должны остаться неизменными. Ответ `0.0234` не зашит в проверку:
ожидаемые частоты/размеры и основная метрика выводятся из текущего плана и CSV.
Побайтовое совпадение CSV проверяется между повторами **внутри каждого job**;
сравнение файлов между OS и точное совпадение floating-point метрик разных OS
не требуются.

Дополнительно smoke проверяет:

- восстановление completed-статуса, плана, метрик, хешей артефактов, verification,
  команды и сохранённого события новым экземпляром `Store`;
- готовность настоящего Python-процесса перед отменой, распространение причины
  abort, отсутствие живого PID и маркера нормального завершения;
- собственный дедлайн `LocalBackend` с exit **124**, без внешнего таймера отмены.

Ошибки процесса, readiness, артефактов, повторяемости, истории или остановки
завершают smoke с ошибкой. В `finally` останавливаются процессы и удаляется
временное состояние. Лимит job — 15 минут, без маскировки зависших тестов.

## Диагностика при ошибке

Только при `failure()` CI загружает диагностический artifact со сроком хранения
7 дней: вывод install/build/tests/smoke и разрешённые файлы smoke-проектов.
`PAPER2_SMOKE_DIAGNOSTICS` включает копирование **только при ошибке smoke**:
`plan.json`, `config.json`, `experiment.json`, `stdout.log`, `stderr.log`,
`artifacts/{metrics.json,samples.csv,plot.svg}`. Копируются обычные файлы до 64 MiB.
На успешном запуске snapshot не создаётся.

Домашняя директория, пользовательское состояние приложения, settings, venv,
переменные окружения, ключи, PDF и аудио не включены в список. CI не получает
секретов провайдеров; checkout не сохраняет Git credentials. Данные smoke
синтетические, собственное хранилище создаётся в новой временной директории.

## OS-specific skips и границы проверки

| Проверка | macOS | Ubuntu |
| --- | --- | --- |
| LocalBackend/Python, cancel/timeout, TERM-resistant потомки | Реальные процессы | Реальные процессы |
| Сохранённая rerun command, другая cwd, пробелы в пути | Выполняется | Выполняется |
| Vast release-policy: create/run запрещены, recovery доступен | Локальные проверки | Локальные проверки |
| Production Electron main/preload/renderer | Собирается | Собирается |
| Electron GUI и IPC end-to-end | Ручная проверка | Ручная проверка, нужен display |

Windows в матрицу не входит; POSIX-регрессии TERM-resistant потомков там явно
пропускаются. Остальной suite использует POSIX-команды, поэтому поддержка Windows
этим CI не заявляется.

CI не выполняет inference Pi/Jev, запросы к настоящему Vast, аренду/удаление
инстансов, загрузку arXiv или доступ к микрофону/Whisper. Vast остаётся явной
заглушкой; recovery проверяется HTTP-фикстурами, а не настоящей арендой.

Автоматический smoke не является Electron GUI smoke: он напрямую использует
тот же `LocalBackend`, `Store` и verifier. Для ручного Electron smoke после
`npm run build` запускайте `npm start` с изолированным `PAPER2_STATE_DIR` и
проверяйте настоящее production-окно, preload и IPC. Web-страница с подставленным
`window.api` не считается проверкой Electron. Историческая проверка macOS в
README не подтверждает GUI на других OS или на каждом новом коммите.

## Повторение локально

Нужны Node 22.19.0, Python 3.12 с venv/ensurepip и POSIX-инструменты выше:

```sh
npm ci
npm run build
npm test
PYTHON="$(command -v python3)" npm run smoke
```

Для сохранения разрешённой диагностики после ошибки:

```sh
PAPER2_SMOKE_DIAGNOSTICS=/tmp/paper2-smoke-diagnostics npm run smoke
```

В отдельной локальной директории результаты останутся до ручного удаления;
временные проекты самого smoke удаляются и при успехе, и при ошибке.

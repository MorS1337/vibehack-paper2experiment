# Methodiy AI

Desktop research harness: текстовый PDF/arXiv → версионированный научный план →
код Python → реальное локальное исполнение → артефакты и проверяемый результат.
Electron + React; ядро, интеграции и оркестрация — TypeScript.

**Текущий MVP по умолчанию работает с явными заглушками агента и без внешних
ключей.** План берётся из фиксированного демо, подготовка кода копирует открытый
эталонный Python. Сам Python, логи, метрики и независимый пересчёт — настоящие.
Это не выдаётся за анализ статьи или генерацию кода LLM. В демо доступен только Local.

Режим **«Настоящий Pi»** оставлен отдельно: pi сам планирует и пишет код; отдельного
coding worker нет. Арендой, исполнением и лимитами управляет harness, не модель.
Русская диктовка через локальный Whisper доступна отдельно от запуска эксперимента.

## Навигация desktop

На macOS отдельная системная полоса заголовка скрыта; штатные кнопки окна
сохранены, окно можно перетаскивать за свободное место верхней панели.
Верхняя панель содержит **Research · Protocol · Evidence** (`⌘1`, `⌘2`, `⌘3`).
Кнопка **Paper** справа показывает/скрывает PDF рядом с текущим разделом;
у неё нет клавиатурного shortcut. Список экспериментов остаётся слева.
До начала исследования вместо рабочих разделов показаны два шага:
**01 Paper → 02 Research brief**. Второй шаг доступен после импорта;
переключение шагов сохраняет введённый brief. `⌘N` начинает новый импорт,
`⌘5` открывает настройки.

Название Methodiy AI используется в интерфейсе, окне, login-потоках и метаданных
приложения. Pixel-grid M в `public/methodiy-mark.svg` — исходник логотипа;
`public/methodiy-icon.png` — производная native-иконка. Внешние шрифты и картинки
для логотипа не загружаются.

## Запуск

Требования: Node.js **>=22.19.0**, npm, Python **3.10+** с `venv`/`ensurepip`.
Для Vast нужны OpenSSH (`ssh`, `scp`, `ssh-keygen`) и `tar`.

```sh
npm ci
npm run build
npm start
# либо сборка и запуск одной командой
npm run dev
```

Первый запуск может скачать бинарник Electron. `npm start` запускает
production-сборку, а не web-имитацию desktop-приложения.

### Быстрый демосценарий без ключей

1. Введите `https://arxiv.org/abs/1910.02884v1` и нажмите **Import paper**.
   Импорт сохраняет PDF и текст без обращения к модели; доступен и локальный PDF.
2. Нажмите **Use this paper →**, затем **Use theorem-check brief**.
3. Оставьте **Demo · explicit stubs**, **Local** и нулевой облачный бюджет.
   Свободный текст брифа в этом режиме не выдаётся за анализ LLM.
4. Нажмите **Prepare demo protocol →**: harness подготовит фиксированный план.
5. Откройте **Review protocol** / вкладку **Protocol**, проверьте план и нажмите
   **Approve v1 & run**. До approval код не выполняется.
6. После настоящего Python-запуска откройте **Evidence**: метрика, CSV, график,
   конфиг, логи и независимая проверка. Повторное исполнение требует нового review.

Заглушка знает только `arXiv:1910.02884v1` и не интерпретирует свободную задачу.
Другая статья/метод требуют настоящего режима Pi. В демо нельзя создать Vast/Auto
запуск даже с ненулевым бюджетом; аренда никогда не начинается.

```sh
npm run typecheck
npm test
npm run smoke
npm audit --omit=dev
```

`smoke` запускает настоящий Python через LocalBackend, независимо пересчитывает
метрику из CSV и сравнивает два запуска с одним plan/config/seed — как для default,
так и для изменённого плана. Сохранённая rerun command выполняется из другой cwd
с пробелами в пути; также проверяются отмена, собственный таймаут backend и история.
Внешние модели, Jev и Vast не вызываются, временные директории удаляются.

CI выполняет сборку/typecheck, весь suite и реальный local smoke на **macOS 15** и
**Ubuntu 24.04** (Node 22.19.0, Python 3.12). Linux-watchdog обязан выполниться без
skip; диагностика сохраняется только при ошибке.
[Состав проверок, OS-specific skips, диагностика и ограничения Electron](docs/ci-verification.md).

## Настройки и авторизация

Панель настроек показывает пять независимых компонентов: pi, Jev, Vast, Whisper
и фактически установленный compactor. Секретные значения не вводятся в renderer:
API-ключи и ручные коды авторизации подключаются штатным pi CLI либо окружением.
Встроенный OAuth поддерживает только несекретные шаги провайдера; ключи не попадают
в эксперимент, snapshots и автоматически не отправляются на Vast.
Для деморежима эти ключи не нужны: реальные статусы подключений не являются блокером локального демо.

[`settings.example.json`](settings.example.json) содержит только безопасные
настройки: модель pi, пути Python/Whisper/SSH. Основной способ редактирования — UI.
Состояние хранится в `app.getPath('userData')/research`. При переименовании
сохранён прежний профиль приложения: на macOS это
`~/Library/Application Support/paper2experiment/research`. Внутренние protocol/IPC
идентификаторы и Pi device ID также сохранены: существующие эксперименты,
сессии и авторизация не требуют миграции. Для изолированной проверки можно
задать `PAPER2_STATE_DIR=/absolute/path`.

### Pi

Закреплён `@earendil-works/pi-coding-agent@1.4.0`. Панель **Settings → Pi**
использует настоящий каталог провайдеров, native auth storage и `ModelRuntime.login`.

1. Для API-ключа или ручного кода выполните штатный `/login` в pi вне renderer
   либо задайте поддерживаемую переменную окружения. Затем обновите список провайдеров.
2. Для поддерживаемого OAuth можно открыть выданную провайдером HTTPS-страницу
   в системном браузере и подтвердить публичный device code или вариант входа.
   Если провайдер запрашивает секретный/ручной ввод, приложение направляет к pi CLI,
   а не собирает его в React-state.
3. Выберите действительно доступную модель и сохраните настройки. Секреты остаются
   в стандартном auth storage Pi, а не в настройках или артефактах эксперимента.

Вход можно отменить; уход из настроек и shutdown отменяют активный поток.
Timeout входа — 10 минут; вход и выполнение эксперимента взаимно исключены.
Auth-ссылки проверяются на принадлежность текущему login flow.
Наличие credentials не доказывает рабочую подписку/баланс или успешный inference:
ошибки провайдера отображаются явно, без публикации секретов.

Штатный вход и выбор модели:
```sh
./node_modules/.bin/pi
# в pi:
/login
/model
```

Либо задайте поддерживаемый ключ, например `ANTHROPIC_API_KEY`, в окружении запуска.
В приложении выберите provider/model. Пустые поля означают первую действительно
доступную модель из pi ModelRuntime, не выдуманный default.

Исследовательский чат Pi сохраняет native session и историю диалога. План, версии,
approval и результаты дополнительно хранятся независимо на диске.
Инструменты подготовки/запуска разрешаются только после review конкретной версии.
Одна approval не разрешает два успешных исполнения; после попыток исполнения Pi
approval расходуется. Новый чат-turn не обнуляет лимит двух технических починок.
Изменение научных условий требует нового плана и review.
Кодирование использует настоящие `read`, `write`, `edit`, `bash` SDK;
окружение Bash фильтруется от ключей, manifest/config сверяются обычным кодом.

### Бесплатный web_search

Агент получает инструмент `web_search(query, max_results?)` на DuckDuckGo HTML
Search: без регистрации, API-ключа и платной подписки. По умолчанию возвращаются
5 результатов, допустимо 1–10: заголовок, исходный HTTPS URL без DuckDuckGo redirect
и текстовый snippet. В чате видны запрос, выполнение и фактический результат.
Например: «Найди исходную статью через web_search и дай ссылки на источники».

Провайдер получает только сформированный запрос, а не PDF или весь разговор;
приватный контекст и credentials в запрос включать нельзя. Snippets — недоверенные
краткие описания, не прочитанные страницы и не научное доказательство.
Это публичная HTML-страница, не API с SLA: CAPTCHA, HTTP 202/403/429 и изменившаяся
разметка дают явную ошибку. Скрытых fallback-провайдеров и автоматических повторов
нет. Один запрос ограничен 20 секундами и 1 MiB ответа; Stop отменяет запрос.

### Inline SVG plots

Графики — часть ответа агента: закрытый блок `svg` отображается прямо в чате,
включая line/scatter/bar plots и интервалы неопределённости, а не только схемы.
Для отрисовки уже известных чисел не нужны Python, matplotlib, Mermaid,
файл картинки или отдельный tool call. Название и доступное описание берутся
из SVG `title`/`desc`; подпись **INLINE FIGURE** не выдаёт рисунок за проверенное
измерение. SVG можно посмотреть как исходник и скачать.

Для measured plots агент сначала читает фактические метрики/данные и указывает
источник. Он не должен придумывать точки или путать аналитическую кривую с
наблюдениями. Расчёт новых измерений по-прежнему требует approval и исполнения
через harness. CSV/JSON проходят независимую проверку; геометрия SVG — presentation,
не ещё одно научное доказательство. `plot.svg` больше не обязателен для демо;
сохранённые графики доступны как явно запрошенный экспорт.

### Диктовка в чате

Кнопка микрофона в composer запускает локальную диктовку: реальный уровень входа,
таймер и лимит 60 секунд, **Cancel** без изменения текста, **Done** для расшифровки.
Распознанный текст вставляется в позицию курсора в редактируемый draft и никогда
не отправляется автоматически. Новый текст можно править, дополнять или отменить.

Whisper работает локально (`whisper-cli` + многоязычная модель, язык `ru`).
Микрофон запрашивается через штатный macOS TCC-диалог; отказ, занятое устройство,
тишина или слишком короткая запись показывают понятную ошибку и не подменяют текст.
**Stop** во время расшифровки отменяет конкретный запрос по id, а не следующий.
Аудио хранится только во временном WAV и удаляется после распознавания.

Важно: локальный CLI распознаёт только после остановки записи — «живого» текста
во время речи нет, и это не имитируется. Модель `base` путает научные термины
(например «Хёффдинга»); для точной диктовки укажите `large-v3-turbo`.
Пути к бинарнику и модели задаются в **Настройки → Whisper**.

### Jev

`@typesafe-ai/sdk@0.7.0`, настоящий `choice` primitive:

```sh
export TYPESAFE_API_KEY=...
```

Ключ выдаётся в [TypeSafe Console](https://console.typesafe.ai/keys).
Для Vast/Auto Jev выбирает только из небольшого набора уже проверенных вариантов
и может ответить `none`. Нет ключа/ошибка API — явная ошибка, **не** скрытый выбор
дешевейшей машины. Local не требует Jev. Auto с положительным облачным бюджетом
требует успешного поиска Vast; при нулевом бюджете облачные варианты не допускаются.

### Vast.ai

Используется документированный REST API из TypeScript. Ключ: `VAST_API_KEY` либо
нативный `~/.config/vastai/vast_api_key`, который создаёт Vast CLI. Значение остаётся
в main/harness-процессе.

```sh
export VAST_API_KEY=...
ssh-keygen -t ed25519 -f ~/.ssh/paper2_vast -C methodiy-ai
chmod 600 ~/.ssh/paper2_vast
```

Укажите приватный SSH-ключ в настройках. Backend регистрирует соответствующий
публичный ключ в аккаунте; учётные данные LLM не загружаются. SSH использует
отдельный `known_hosts` для запуска, `accept-new`, без `StrictHostKeyChecking=no`.

Один поддерживаемый образ:
`pytorch/pytorch:2.4.0-cuda12.4-cudnn9-runtime`.

До Jev код фильтрует фактические предложения по CPU/RAM/VRAM/disk, надёжности,
verified/rentable, архитектуре amd64, CUDA ≥ 12.4, доступности direct SSH и бюджетам.
Неизвестные параметры совместимости отклоняются. `dph_total` учитывается один раз как all-in тариф
заданного `allocated_storage`. Оценка содержит резерв setup/экспорта и сети.
Выбранное предложение перепроверяется перед созданием; увеличение утверждённого
тарифа требует нового выбора. Платный запуск — только после отдельного approval.
Точечный запрос использует `ask_contract_id`: на проверенном Vast API фильтр `id`
не находит тот же offer, хотя в ответе `id` совпадает с `ask_contract_id`.
Фиксированный образ опубликован только для Linux/amd64:
[метаданные Docker Hub](https://hub.docker.com/v2/repositories/pytorch/pytorch/tags/2.4.0-cuda12.4-cudnn9-runtime).
Проверка CUDA использует поле API `cuda_max_good` — это
[реальное имя CLI-алиаса `cuda_vers`](https://github.com/vast-ai/vast-cli/blob/master/vast.py#L1035-L1037).

### Whisper: русский голосовой ввод

```sh
git clone https://github.com/ggml-org/whisper.cpp.git
cd whisper.cpp
cmake -B build
cmake --build build -j --config Release
sh models/download-ggml-model.sh large-v3-turbo
```

Укажите абсолютные пути `build/bin/whisper-cli` и `models/ggml-large-v3-turbo.bin`.
Для macOS также доступен `brew install whisper-cpp`. Модели `.en` не подходят:
нужна многоязычная модель. `tiny` использована только для smoke; для русской научной
диктовки рекомендуется более крупная модель и обязательное чтение расшифровки.

```sh
ffmpeg -i record.m4a -ar 16000 -ac 1 -c:a pcm_s16le /tmp/russian.wav
whisper-cli -m /absolute/path/ggml-large-v3-turbo.bin -f /tmp/russian.wav -l ru -nt
```

Кнопка микрофона записывает не более 60 секунд. Речь преобразуется в редактируемый
текст задачи; сама запись никогда не запускает эксперимент. Транскрипция локальная,
отмена/закрытие приложения завершают child process и удаляют временный WAV.

При первом нажатии разрешите доступ к микрофону в системном диалоге. В macOS
при `npm start` приложение называется **Electron**: Системные настройки →
Конфиденциальность и безопасность → Микрофон. После изменения разрешения
перезапустите приложение. Запрос доступа завершается ошибкой через 15 секунд;
кнопка **«Отменить»** и Esc работают при ожидании доступа и распознавании, а также
во время записи. Закрытие формы отменяет диктовку. Запоздалый ответ ОС освобождает
микрофон и не добавляет текст. Во время записи показано фактическое имя устройства;
чтобы сменить микрофон, выберите вход в системных настройках звука до записи.

`npm start` использует `NSMicrophoneUsageDescription` из поставляемого Electron.app.
При будущей упаковке собственного macOS bundle нужно сохранить этот ключ с описанием
локальной диктовки; для подписанного hardened-runtime bundle также нужно разрешение
`com.apple.security.device.audio-input`. Упаковка и подпись отдельного приложения
в этом репозитории пока не настроены. См. [Electron systemPreferences](https://www.electronjs.org/docs/latest/api/system-preferences#systempreferencesaskformediaaccessmediatype-macos)
и [Apple Audio Input Entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.audio-input).

Ручная проверка: нажмите **«Наговорить задачу»**, произнесите «Проверить границу
Хёффдинга для независимых случайных величин и сравнить вероятность отклонения
с теоретической оценкой», остановите запись и исправьте распознанный текст.
Проверьте, что карточка эксперимента не создана. Повторите с отменой и закрытием
формы: индикатор использования микрофона должен погаснуть, текст не добавляется.

### SmartCompact

`smartcompact@0.1.8` из [coffeecoproject/SmartCompact](https://github.com/coffeecoproject/SmartCompact)
подключён через pi `DefaultResourceLoader` и механизм расширений. UI получает
настоящие события pi/расширения, а не симуляцию сокращения контекста. Штатный allow
line — 200k токенов; короткая сессия может не потребовать compaction. Планы, состояние
и результаты хранятся на диске независимо от контекста модели.

## Рабочий сценарий настоящего режима Pi

1. Добавьте текстовый PDF или HTTPS arXiv URL, задачу, при необходимости авторский
   HTTPS-репозиторий и папку данных. Выберите Local/Vast/Auto, время, бюджет, cleanup.
2. Создайте план. Pi получает извлечённый источник с номерами страниц. Цитаты должны
   существовать на указанных страницах; выдуманные ссылки отвергаются.
3. Исправьте JSON ExperimentSpec. Каждое сохранение создаёт новую версию; перед
   исполнением научные условия замораживаются. `missing` нужно разрешить явно.
4. Запустите подготовку. Pi создаёт проект сам. Если указана авторская реализация,
   она реально клонируется, записываются URL/commit; независимая реализация помечается.
5. Harness исполняет проект, пишет логи и PID. Техническая ошибка допускает максимум
   две починки кода через pi, но не изменение научных условий без новой версии плана.
6. Результаты: метрики, конфиг, логи, графики, артефакты с SHA-256, независимая проверка
   демо, ограничения сопоставимости, команда повторного запуска и открытие папки.

«Процесс завершился» **не означает** «результат статьи воспроизведён». Для общего
эксперимента проверка формата артефактов не доказывает научную эквивалентность.

## Научный демо-кейс

[`demos/bernoulli-hoeffding`](demos/bernoulli-hoeffding/README.md): независимая
симуляция односторонней границы Хёффдинга для Bernoulli(p). Открытый текстовый
источник — [Introduction to Concentration Inequalities, arXiv:1910.02884v1](https://arxiv.org/abs/1910.02884v1),
страницы 8–9. Исходники и детерминированный генератор данных включены.

```sh
sh demos/bernoulli-hoeffding/source/fetch-source.sh
# либо используйте кнопку «Заполнить демо Хёффдинга» для запуска с заглушками
npm run smoke
```

Для `n=160, p=0.5, epsilon=0.08, R=10000`: измеренная доля `0.0234`, точная
биномиальная вероятность `0.023883498014142024`, верхняя граница
`0.1289926310365194`. Верификатор пересчитывает долю из counts CSV, не читает ответ
обратно из metrics.json. Это проверка теоремы, не опубликованного численного
результата: `implementation=independent`, `publishedValue=null`, `comparable=false`.

## Проверка Vast с реальным аккаунтом

Этот сценарий **не выполнялся** в разработке. Нужны собственный аккаунт, баланс,
ключ Vast, TYPESAFE_API_KEY, SSH-ключ и явно разрешённый бюджет.

1. Настройте авторизацию и SSH, запустите приложение. Проверьте реальные статусы.
2. Выберите Vast/Auto, положительные hourly/total caps, короткий лимит, например
   300 секунд, cleanup=`destroy`. Создайте и сохраните научный план.
3. На approval проверьте offer ID, ресурсы, all-in тариф, резерв итога и время.
   До подтверждения в Vast Console не должно появиться нового инстанса.
4. Подтвердите. ID должен сразу попасть в run.json; наблюдайте boot, SSH, upload,
   подготовку окружения и реальный процесс. Ключи LLM на инстансе отсутствуют.
5. После завершения проверьте локальный export/manifest.json, SHA-256 архива и файлов,
   метрики/график/логи. В Console убедитесь, что инстанс действительно удалён.
6. Повторите отмену во время boot и во время вычисления. Проверьте остановку процесса
   и cleanup. Удалённый watchdog использует оставшееся время, включая подготовку.
7. Проверьте ошибку экспорта: SSH/SCP/checksum failure оставляет инстанс, показывает
   `cleanupRequired` и предупреждение о тарификации. Повторный cleanup сначала
   выгружает файлы. Отсутствующие метрики после отмены — научная ошибка, не ошибка
   передачи: проверенный snapshot частичных результатов/логов допускает cleanup.
8. При потерянном ответе create найдите инстанс по сохранённой уникальной метке.
   Неопределённость блокирует вторую аренду, а startup/cleanup повторяют reconciliation.
   Пустой/неуспешный ответ списка не выдаётся за доказательство отсутствия аренды;
   может потребоваться ручная сверка с Vast Console/поддержкой.
9. При cleanup=`retain` аренда остаётся платной по выбору пользователя. Завершите
   её в Console. Сохраните реальные offer/instance IDs, цену и результат проверки.

## Архитектура и границы безопасности

- `src/main`: Electron main/preload; contextIsolation, sandbox, nodeIntegration=false,
  локальный secure protocol/CSP, проверка IPC sender, узкий типизированный API.
- `src/renderer`: React; нет Node API, ключей, прямого SSH или процессов.
- `src/core`: отдельный Electron utility process; атомарные JSON, JSONL, версии планов,
  импорт источника, статусы, валидация и отчёты.
- `src/integrations`: pi + настоящее расширение SmartCompact, Jev, whisper.cpp.
- `src/compute`: общий prepare/run/getStatus/streamLogs/cancel/collectArtifacts/cleanup,
  LocalBackend и VastBackend. На Vast передаются проект/данные, не агенты/ключи.

**Локальный код и shell-инструменты pi — не OS-песочница.** Они действуют с правами
пользователя. Запускайте только понятные задачи/источники, проверяйте код; не используйте
приложение для обработки враждебного кода на машине с ценными данными. Изоляция
renderer не означает изоляцию научного Python. Bash окружение фильтруется, но это
не защита от намеренного чтения доступных пользователю файлов.

Фиксированные границы первой версии: текстовые PDF до 40 MiB, без OCR; один активный
запуск/инстанс; Python; один cloud image; локальный CUDA GPU определяется через
`nvidia-smi` (Apple Metal не объявляется CUDA-вариантом); голос только для задачи.
Импорт/экспорт ограничены размерами и безопасными относительными путями; причины
отказа показываются явно.

Оценка Vast — не гарантия счёта провайдера: при потере сети процесс можно ограничить
watchdog, но недоступный API не гарантирует остановку тарификации. Сохранение данных
при ошибке экспорта важнее молчаливого удаления инстанса; риск расходов виден в UI.
После аварийного перезапуска неизвестный локальный PID не убивается вслепую.
